Start with the use, not a percentage

A sensible compression workflow

A lower setting is useful only if the export still works where you intend to use it.

  1. 01

    Start from your original

    Upload a JPG, PNG or WebP. Keep a separate original; repeatedly exporting a lossy image can accumulate visible artifacts.

  2. 02

    Choose a starting setting

    Try 85% for detail you want to inspect carefully or 70% for an everyday copy. The setting is not the percentage of file size you will save.

  3. 03

    Use a target when you have one

    Enter a preferred size in KB if a form or upload has a limit. PMW searches for a smaller export, but the target is best effort.

  4. 04

    Inspect the result

    Check edges, text, gradients and the returned width/height. PMW can reduce dimensions while pursuing its size target. Download only when both detail and size are suitable.

Practical starting choices

Website photography

Choose the display dimensions first in Resizer, then inspect a compression export. Avoid sending a huge original for a small on-screen image.

Screenshots and logos

Prioritize readable text and clean edges. Inspect PNG output dimensions; a smaller pixel frame can make small lettering harder to read. Keep a vector original separately if you have one.

Attachments and forms

Use the receiving site’s actual byte limit as the target. Check the downloaded file rather than assuming that the quality percentage is a size guarantee.

Work backwards from the limit

Build a useful size budget

Illustrative numbers, not measured savings

An upload limit is a boundary, not a quality setting.

Imagine a form that accepts a file smaller than 500KB. A 1.8MB original will not fit, but moving the quality slider to 50% does not mean that it will become 900KB—or that it will pass the form’s limit.

Choose a preferred target with a little room below the limit, such as 450KB. Inspect PMW’s returned size and dimensions. If the result is still too large, make a new attempt from your original, or first use the Resizer to choose fewer pixels when the form allows it.

A receiving site may count kilobytes differently. PMW’s target field treats 1KB as 1,024 bytes. The receiving site’s validation is the final check; a number that looks close is not a guarantee of acceptance.

Keep two copies. Give the sharing copy a descriptive name such as mountain-web.jpg and keep the original separately. That makes it easier to revisit quality choices without repeatedly compressing an already compressed file.

Look beyond the size number

Four places to inspect your picture

Compare at the intended viewing size first, then zoom in where detail matters. Do not judge a full-size image only from a tiny preview.

A · Fine edges

Small lettering and outlines

Look for halos around text, jagged diagonal lines and soft edges. If a logo or screenshot needs precise detail, a high setting is a starting point—not a substitute for inspecting the exported dimensions.

B · Smooth tones

Skies, gradients and shadows

Look for bands in a smooth sky or blocks in dark areas. These can become more noticeable after another app processes your upload. Keep an original so you can choose a different export if needed.

C · Texture

Leaves, hair and fabric

Fine texture can turn into a soft patch even while large shapes look unchanged. Decide whether that detail matters to the actual use: a small attachment and a large portfolio image have different needs.

D · Pixel frame

Width and height after export

A lighter result may also be smaller in pixels. Confirm that it still has enough resolution for the destination. The compressor can downscale while searching for the target size.

A deliberate second attempt

What to change when the first copy is not right

01
Too heavy

The image looks good, but the file is too big.

Check whether it contains many more pixels than the destination needs. Resize from the original to a suitable proportional frame, then compress that copy. If a PNG photograph remains large, compare a WebP or JPG export in the Converter when the destination accepts it.

Right dimensions → suitable format → inspect compression

02
Too soft

The file fits, but important detail has disappeared.

Start again from the original. Raise the quality setting and check the returned dimensions. If the size requirement is extremely tight, decide which matters more: a smaller display frame or visible artifacts at full size. No percentage can remove that trade-off.

Original → higher setting → compare at viewing size

03
Wrong destination

The export looks fine, but an upload rejects it.

Read the accepted formats, maximum dimensions and byte limit together. A small WebP is not useful to a form that accepts only JPG. Use the Converter for a format requirement and the Resizer for a pixel requirement rather than repeating compression blindly.

When the result needs a second look

Compression questions answered

Does 70% mean a 30% smaller file?

No. It is a requested quality setting. Format, image detail, the original encoding and the selected pixel scale affect the size. PMW’s PNG path handles quality differently from JPEG/WebP.

Can I keep the original width and height?

There is no dimension-lock control in this compressor. Its size search can downscale the image. Inspect the result dimensions; keep the original when a full-resolution file is essential.

Why is the target size not reached?

The target is preferred rather than guaranteed. The tool can return a smaller file that is still above the target, or report that an already optimized image could not be made smaller.

Will transparent areas remain transparent?

PNG and WebP exports can retain alpha. JPG cannot. This compressor keeps the input format; use the converter if you want a different one.

What are the free limits?

The current free allowance is nine compressions per day, one image at a time, with a 10MB per-file limit and large-dimension restrictions. Premium enables batches/higher allowances; device memory still limits large images.

Where does the image go?

The compressor reads and encodes the file in your browser rather than uploading its contents to PMW. The page still makes ordinary requests for its libraries and analytics. Save the export before closing the tab.
